# رَفّ · جرد الأنظمة وخطة التوسعة

البنية: واجهة ثابتة (HTML/CSS/JS بلا إطار) على GitHub Pages + Supabase (PostgreSQL، Auth، Storage) كـ Backend.
كل منطق حسّاس (الأسعار، المخزون، الخصم، الصلاحيات) بيتنفّذ داخل قاعدة البيانات بدوال `security definer` وقواعد RLS،
فما في شي بيعتمد على ثقة المتصفح.

## ١. الموجود ويشتغل (ما رح ينبنى من جديد)

| النظام | الحالة |
|---|---|
| الكتالوج، صفحة المنتج، صور متعددة، مقاسات/ألوان | ✅ |
| البحث (بيفهم الإملاء العربي) + الترتيب + التصنيفات | ✅ |
| السلة، إتمام الطلب، تسعير وفحص مخزون على السيرفر | ✅ `place_order` |
| طرق الدفع: عند الاستلام، PayPal.me، تحويل بنكي | ✅ (بلا بوابة دفع مدمجة) |
| الطلبات: حالات، سجل، فاتورة للطباعة، تصدير CSV، إرجاع المخزون عند الإلغاء | ✅ |
| حسابات الزبائن: تسجيل، دخول، استعادة كلمة السر، عناوين، مفضلة، حذف الحساب | ✅ |
| تتبّع الطلب للضيوف | ✅ |
| الكوبونات: نسبة/مبلغ/توصيل، حد أدنى، تواريخ، حد استعمال | ✅ |
| التقييمات (للمشترين فقط + موافقة) | ✅ |
| نظام الإجابة: إجابات فورية، محادثات، أسئلة المنتجات | ✅ |
| لوحة الإدارة: إحصاءات، طلبات، منتجات، عملاء، إعدادات، صفحات | ✅ |
| SEO: Product JSON-LD، OG، sitemap، robots | ✅ |
| أمان: CSP صارمة، RLS، حماية من XSS، حد للرسائل | ✅ |
| اختبارات: ٥٠ اختبار Playwright + اختبارات SQL + Lighthouse + axe | ✅ |

## ٢. موجود بس ضعيف (بيتطوّر بمكانه)

| النظام | الضعف | التطوير |
|---|---|---|
| صلاحيات الإدارة | مدير واحد بصلاحية كاملة | أدوار: مالك، مدير، مخزون، خدمة عملاء + سجل تدقيق |
| المخزون | رقم واحد بلا سجل | سجل حركات، تنبيهات نقص، حد إعادة طلب، جرد |
| المقاسات/الألوان | خيارات بلا مخزون منفصل | متغيّرات بمخزون وسعر وSKU لكل وحدة |
| الطلبات | تغيير الحالة يدوي فقط | مرتجعات واستردادات، رقم شحنة وشركة شحن |
| العملاء | قائمة من الطلبات | ملف عميل، مجموعات، شرائح تلقائية، نقاط ولاء |
| الكوبونات | كود واحد لكل طلب | قيود على تصنيف/منتج، خصم أول طلب، لكل عميل مرة |
| التحليلات | مبيعات يومية | أرباح (سعر التكلفة)، أداء المنتجات، توقع مبيعات |
| SEO | بيانات منتج بالواجهة | sitemap تلقائي للمنتجات |

## ٣. غير موجود (بيتضاف)

إدارة المستودعات والموردين وأوامر الشراء، سلّة متروكة، توصيات المنتجات، شوهد مؤخراً، العروض المجمّعة،
الإحالة، الضرائب، تقارير مالية، Google Analytics / Meta Pixel، تعدد العملات واللغة، التحقق بخطوتين، كشف الاحتيال.

## ٤. بيحتاج خدمة خارجية (بيتجهّز برمجياً بلا تفعيل ولا اشتراك)

| النظام | الخدمة | الوضع |
|---|---|---|
| بوابة دفع بالبطاقة مباشرة | Stripe / Tap / PayTabs | بيحتاج حساب تاجر + Edge Function للتوقيع |
| رسائل الإيميل التلقائية | Resend / SendGrid | قالب ومنطق جاهز، بيشتغل لما تحط مفتاح |
| مهام خلفية مجدولة | `pg_cron` بـ Supabase (مجاني) | بيتفعّل بسطر SQL من لوحة Supabase |
| Webhooks | Supabase Database Webhooks (مجاني) | جدول أحداث جاهز يتربط بأي رابط |
| تحليلات خارجية | Google Analytics / Meta Pixel | خانة المعرّف بالإعدادات، ما بيتحمّل شي قبل ما تحطه |

## ٥. ترتيب التنفيذ

1. الأساس: الأدوار والصلاحيات + سجل التدقيق + سجل حركات المخزون وتنبيهات النقص.
2. المتغيّرات بمخزون منفصل + التعديل الجماعي للمنتجات.
3. المرتجعات والاستردادات + الشحن (شركة ورقم تتبّع) + الضرائب.
4. CRM: ملف العميل، المجموعات، الشرائح، نقاط الولاء، الإحالة.
5. التسويق: محرك كوبونات متقدم، العروض المجمّعة، السلة المتروكة، التوصيات، شوهد مؤخراً.
6. التحليلات: الأرباح، أداء المنتجات، التوقع، التقارير المالية.
7. المستودعات والموردين وأوامر الشراء.
8. التحقق بخطوتين، كشف الاحتيال، GA/Pixel، تعدد العملات.

كل مرحلة: SQL مختبر على PostgreSQL حقيقي → واجهة بلوحة الإدارة → اختبارات Playwright → تشغيل كامل الاختبارات مرتين.
